# Практична робота №9

**Тема:** Робота з модулем MSSP в режимі I2C.

**Дисципліна:** Мікроконтролери та їх програмування  
**Виконала:** Петращук Марія

**Середовище розробки:** MPLAB X IDE v6.35, XC8

## 1. Мета роботи

Навчитися використовувати модуль послідовного синхронного порту MSSP мікроконтролера PIC16F877A у режимі I2C для організації обміну інформацією із зовнішньою пам'яттю EEPROM 24C16. Ознайомитися з принципами запису та читання даних, а також перевірити роботу розробленої програми.

## 2. Завдання роботи

1. Ознайомитися з принципами роботи протоколу I2C.
2. Виконати ініціалізацію мікроконтролера PIC16F877A.
3. Налаштувати модуль MSSP у режимі I2C з частотою 100 кГц.
4. Реалізувати функції формування START і STOP.
5. Реалізувати передавання та приймання байтів інформації.
6. Записати один байт за адресою `0x00` у пам'ять EEPROM 24C16.
7. Зчитати записаний байт.
8. Відобразити результат на світлодіодах PORTD.
9. Перевірити роботу схеми у Proteus.

## 3. Теоретична частина

### 3.1. Протокол I2C

I2C — послідовний синхронний інтерфейс обміну інформацією між електронними пристроями.

Для передавання даних використовуються дві сигнальні лінії:

- **SDA** — лінія передавання даних.
- **SCL** — лінія синхронізації.

Обмін відбувається між ведучим пристроєм (Master) і веденим пристроєм (Slave).

У цій роботі ведучим є PIC16F877A, а веденим — EEPROM 24C16.

Передавання починається сигналом START і завершується сигналом STOP. Після передавання байта приймач формує підтвердження ACK або NACK.

### 3.2. Модуль MSSP

MSSP — апаратний модуль мікроконтролера, призначений для синхронного послідовного обміну даними.

Він підтримує режими SPI та I2C.

Для керування MSSP використовуються регістри:

| Регістр | Призначення |
|---|---|
| SSPCON | Керування модулем MSSP |
| SSPCON2 | Формування START, STOP, ACK та інших операцій |
| SSPSTAT | Контроль стану передавання |
| SSPADD | Налаштування швидкості I2C |
| SSPBUF | Буфер передавання та приймання |

### 3.3. Пам'ять EEPROM 24C16

EEPROM 24C16 — енергонезалежна пам'ять обсягом 16 Кбіт (2048 байтів).

Вона дозволяє записувати та зчитувати інформацію через інтерфейс I2C.

Для першого блоку пам'яті використовуються адресні байти:

- `0xA0` — запис.
- `0xA1` — читання.

У роботі використовується комірка з адресою `0x00`, до якої записується значення `0xA5`.

## 5. Хід виконання роботи

### 5.1. Створення проєкту

У MPLAB X IDE створено проєкт `Practical9_I2C` для мікроконтролера PIC16F877A.

Встановлено тактову частоту 4 МГц і вибрано компілятор XC8.

Розроблено програму `main.c`, яка забезпечує обмін інформацією із зовнішньою EEPROM через апаратний модуль MSSP.

Програму скомпільовано з результатом `BUILD SUCCESSFUL`.

### 5.2. Ініціалізація модуля MSSP

Для роботи I2C використано контакти:

- RC3/SCL — контакт 18.
- RC4/SDA — контакт 23.

Обидва контакти налаштовано як входи.

Частоту I2C встановлено на рівні 100 кГц.

Значення регістра SSPADD визначено за формулою:

**F_I2C = Fosc / (4 × (SSPADD + 1))**

Для Fosc = 4 МГц отримано:

**SSPADD = 9**

Фрагмент програми:

```c
void I2C_Init(void)
{
    TRISCbits.TRISC3 = 1;
    TRISCbits.TRISC4 = 1;

    INTCONbits.GIE = 0;
    INTCONbits.PEIE = 0;

    SSPSTAT = 0x80;
    SSPCON = 0x28;
    SSPCON2 = 0x00;
    SSPADD = 9;
}
```

### 5.3. Реалізація функцій обміну I2C

У програмі реалізовано такі функції:

- `I2C_Start()` — початок сеансу передавання.
- `I2C_Restart()` — формування повторного START.
- `I2C_Stop()` — завершення сеансу.
- `I2C_Trans()` — передавання одного байта.
- `RECIEVE_ACK()` — приймання байта з підтвердженням.
- `RECIEVE_NACK()` — приймання останнього байта без підтвердження.

Функції використовують регістри MSSP для керування обміном між мікроконтролером та EEPROM.

### 5.4. Запис даних до EEPROM

Для запису створено функцію `EEPROM_WriteByte()`.

Послідовність операцій:

1. Формування START.
2. Передавання адресного байта `0xA0`.
3. Передавання адреси комірки `0x00`.
4. Передавання значення `0xA5`.
5. Формування STOP.
6. Очікування завершення внутрішнього циклу запису.

Фрагмент програми:

```c
write_success = EEPROM_WriteByte(
    EEPROM_ADDR,
    TEST_DATA
);
```

### 5.5. Зчитування даних із EEPROM

Для читання створено функцію `EEPROM_ReadByte()`.

Послідовність операцій:

1. Формування START.
2. Передавання адресного байта `0xA0`.
3. Передавання адреси комірки `0x00`.
4. Формування повторного START.
5. Передавання адресного байта `0xA1`.
6. Приймання байта.
7. Формування NACK.
8. Завершення обміну сигналом STOP.

Фрагмент програми:

```c
read_success = EEPROM_ReadByte(
    EEPROM_ADDR,
    (uint8_t *)&read_data
);
```

## 7. Відповіді на контрольні запитання

**1. Що таке протокол I2C?**

I2C — синхронний послідовний інтерфейс, який використовує дві сигнальні лінії SDA та SCL.

**2. Для чого призначений модуль MSSP?**

Модуль MSSP забезпечує апаратну реалізацію послідовного обміну інформацією в режимах SPI та I2C.

**3. Яке призначення сигналу START?**

Сигнал START позначає початок сеансу передавання даних.

**4. Яке призначення сигналу STOP?**

Сигнал STOP завершує сеанс обміну та звільняє шину I2C.

**5. Що означає ACK?**

ACK — підтвердження успішного приймання байта інформації.

**6. Що означає NACK?**

NACK — відсутність підтвердження. Під час читання останнього байта ведучий використовує NACK для завершення приймання.

**7. Для чого використовується регістр SSPADD?**

Він визначає частоту тактового сигналу I2C у режимі ведучого.

**8. Для чого призначений регістр SSPBUF?**

Для зберігання байта, який передається або приймається модулем MSSP.

**9. Чому на лініях SDA та SCL потрібні підтягувальні резистори?**

Вони забезпечують високий логічний рівень, коли пристрої не притягують лінії до землі.

**10. Як здійснюється запис байта в EEPROM?**

Мікроконтролер формує START, передає адресу EEPROM, адресу комірки та байт даних, після чого формує STOP.
